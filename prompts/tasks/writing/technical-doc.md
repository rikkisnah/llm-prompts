# Technical Documentation

Write clear technical documentation following these principles:

## Structure
1. **Overview**: What and why (2-3 sentences)
2. **Prerequisites**: Required knowledge, tools, access
3. **Core Content**: Organized by task or concept
4. **Examples**: Real, working examples
5. **Troubleshooting**: Common issues and solutions
6. **References**: Links to related docs

## Style Guidelines
- Lead with the most important information
- Use active voice and imperative mood
- One idea per paragraph
- Code examples should be complete and runnable
- Tables for comparing options or listing parameters
- Diagrams for architecture and flow (describe if not creating)

## Code Blocks
- Specify language for syntax highlighting
- Include comments for non-obvious lines
- Show expected output where helpful
- Use placeholders consistently: `<PLACEHOLDER>`

## Anti-Patterns
- Don't bury the lede (put key info first)
- Avoid wall-of-text paragraphs
- Don't assume context not established
- Skip obvious statements ("This document describes...")
