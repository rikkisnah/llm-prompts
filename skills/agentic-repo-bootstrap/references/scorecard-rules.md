# Scorecard Rules

The scorecard enforces the repo operating contract, not arbitrary style preferences.

Required capabilities:

- Deterministic and dependency-free where practical.
- Text output.
- JSON output.
- `--min-score` gate behavior.
- Regression tests.
- Secret scanning for obvious risky patterns.
- Clean-code heuristics for measurable issues.

Core dimensions:

- Instruction parity.
- Memory governance.
- Context placeholder governance.
- Documentation accuracy.
- Workflow docs.
- Build and tooling.
- Formatting and linting.
- Test quality.
- Type or contract safety.
- Clean code.
- Module cohesion.
- Duplication.
- Security and secret safety.
- Runtime contract.
- Agentic reviewability.
