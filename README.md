# llm-prompts

Personal library of LLM prompts and reusable Claude Code / Codex CLI **skills**, plus a small Python CLI that installs the skills into `~/.claude/skills` and `~/.codex/skills`.

## Purpose

- `prompts/` — paste-into-the-chat Markdown prompts for the kinds of documents I write often (summaries, design docs, articles, LinkedIn posts, blog posts, etc.).
- `skills/` — prompts promoted into installable skills that Claude Code or Codex CLI auto-invoke when their description matches the user's request.
- A `uv`-backed stdlib-only Python CLI (`skills_manager`) that syncs `skills/` into both tools' skill directories so any new clone can install them with one command.

The repository also carries an agentic engineering governance layer (scorecard, validation gates, clean-code rules, workflow docs) generated by the `agentic-repo-bootstrap` skill — so this repo is both a *library of skills* and a *worked example* of using them.

## Layout

```
prompts/                  Markdown prompts (UPPER-KEBAB-CASE filenames, e.g. CREATE-PR.md)
skills/                   Installable Claude Code / Codex skills
  <skill-name>/SKILL.md   Skill manifest with name + description frontmatter
  <skill-name>/prompts/   Large reusable prompts referenced by the skill
  <skill-name>/references/ Background notes and command patterns
  <skill-name>/scripts/   Optional helper scripts shipped with the skill
  <skill-name>/assets/    Optional templates and other static assets
src/skills_manager/       Stdlib-only Python CLI used by `make sync`
tests/                    Unit tests for the CLI and the scorecard
scripts/                  Helper scripts and example tool configs
docs/agent/               Clean-code, review, testing, and language guides
docs/adr/                 Architecture Decision Record template
AGENTS.md                 Authoritative agent operating contract
CLAUDE.md -> AGENTS.md    Symlink so Claude Code reads the same file as Codex
MEMORY.md                 Durable non-secret project context
CONTEXT.md                Temporary branch handoff placeholder
INSTALL.md                Setup workflow
DEVELOP.md                Daily development loop
CREATE-PR.md              Local PR handoff workflow
```

## Quick Start

```bash
make setup        # uv sync (no-op if no runtime deps)
make sync         # install skills/ into ~/.claude/skills and ~/.codex/skills
make validate     # full local gate: lint + tests + score-gate
```

## Install the skills

```bash
make sync         # both Claude Code and Codex CLI
make list         # show source skills + what's installed for each tool
```

`make sync` only adds and refreshes the skills shipped here; it never deletes skills you installed from other sources unless their directory names collide.

Target a single tool with the underlying CLI:

```bash
PYTHONPATH=src python3 -m skills_manager sync --home --skills skills --target claude
PYTHONPATH=src python3 -m skills_manager sync --home --skills skills --target codex
```

## Validation gates

```bash
make format       # apply safe formatting when configured
make test         # run unit tests (skills_manager + scorecard)
make lint         # syntax / compileall
make score        # print governance scorecard
make score-gate   # fail unless every scorecard dimension is 10/10
make check        # lint + test
make validate     # check + score-gate (the handoff gate)
```

`make validate` is the full local gate. Run it before any handoff that touches code, packaging, config, Makefile targets, validation logic, or workflow docs.

## Prompt format

Markdown with optional YAML frontmatter:

```markdown
---
tags: [writing, summary]
---
# Prompt Title

Prompt content here...
```

## Skill format

Each skill is a directory with a `SKILL.md` manifest:

```markdown
---
name: my-skill
description: "One sentence that tells Claude/Codex when to invoke this skill."
---

<!-- #ai-assisted with OCA/OpenAI Model with human supervision -->

# My Skill
...
```

The skill's `description` is the trigger — make it specific so it fires on the right requests and stays out of the way on the wrong ones. See `skills/skill-authoring/` for the meta-skill that creates new skills.

## Agentic Development Workflow

- Read `AGENTS.md` before changing code.
- Use `MEMORY.md` only for durable non-secret project context.
- Use `CONTEXT.md` only as a short-lived branch-local placeholder.
- Run `make validate` before handoff when code, packaging, config, Makefile, validation, or workflow behavior changes.
- Treat documentation drift as a bug.

## Security And Secrets

Never commit secrets, credentials, private keys, bearer tokens, raw auth files, customer data, huge logs, or local-only environment files. Use safe placeholders such as `<token>`, `<secret>`, `REPLACE_ME`, or committed `.env.example` files.
